# Руководство оператора IJKbot

Короткий сценарий подключения, картографирования и навигации есть в [README](../README.md#быстрый-старт). Команды `./ijk` и `scripts/` запускаются из корня репозитория. Установку бортовых зависимостей, подготовку USB и пробный запуск на Orin описывает [инструкция по Jetson](JETSON_ORIN_MIGRATION.md).

## Сборка и тесты

На Ubuntu с нативным ROS 2 Jazzy соберите пакеты в окружении ROS:

```bash
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install
source install/setup.bash
```

Для ноутбука с готовым окружением Pixi укажите путь к его `pixi.toml` и запустите сборку из корня IJKbot:

```bash
pixi run --manifest-path "$PIXI_PROJECT_MANIFEST" colcon build --symlink-install
```

Установите зависимости из [requirements.txt веб-пульта](../tools/ijk/web/requirements.txt) в окружение, в котором запускается `./ijk ui`. Для проверки CLI, веб-пульта, телеметрии и датчиков запустите в активированном окружении ROS с собранным overlay:

```bash
python3 -m pytest -q tests/test_ijk_cli.py tests/test_ijk_ui.py \
  tests/test_ijk_telemetry.py src/terrain/test \
  src/vision/test/test_victim_yolo.py src/vision/test/test_zxing_qr_launch.py
```

Для проверки собственных пакетов ROS используйте `colcon test` и `colcon test-result --verbose`. Сценарные тесты миссии описаны в [README пакета brain](../src/brain/README.md#проверка).

## Связь и обслуживание

Проверьте, что с ноутбука доступен SSH к бортовому пользователю, а ROS-процессы с обеих сторон используют один `ROS_DOMAIN_ID`. Значение в конфигурации IJKbot — `42`, транспорт — CycloneDDS. При нескольких адресах на интерфейсе `./ijk` выбирает маршрут к фактическому адресу робота. Для ROS-процессов, запущенных вручную, используйте тот же домен и сетевой интерфейс.

```bash
./ijk discover
./ijk doctor
./ijk ops timesync
./ijk logs
```

При ошибках TF о времени сверяйте `chronyc tracking` и `chronyc sources -v` на обоих компьютерах. `./ijk ops timesync` оценивает смещение и корректирует время при превышении порога. Флаг `--force` запускает коррекцию при любом измеренном смещении. Для установки времени нужны права на `sudo date` на борту. При доступном `sudo chronyc makestep` команда также применяет поправку Chrony.

| Команда | Назначение |
| --- | --- |
| `./ijk ops update` | Собрать локальный workspace и обновить бортовой из `origin/dev`. Перед обновлением остановите профиль и сохраните текущую карту. |
| `./ijk ops wifi --profile list` | Показать профили из конфигурации. `--profile scan` выводит доступные сети. |
| `./ijk ops wifi --profile tplink` | Применить выбранный профиль Wi-Fi. После смены сети переподключитесь по новому адресу. |
| `./ijk ops bag-export --bag /путь/к/rosbag` | Экспортировать одометрию и команды скорости в CSV и построить графики. |
| `./ijk ops save-map --name hall_101` | Сохранить активную `/map` в YAML и PGM. Для новой карты используйте свободное имя. |
| `./ijk stop` | Остановить профиль. В веб-пульте для экстренной остановки доступен E-STOP. |

Для работы без робота запустите `./ijk ui --mock --no-browser`. В реальном режиме бортовой узел `ijk_robot_monitor` должен передавать свежую телеметрию и подтверждать управление. Для локального доступа можно запустить `./ijk ui --host 127.0.0.1 --port 8080`. Доступ с других устройств используйте в доверенной сети, поскольку веб-пульт работает без пароля. [Управление и потеря связи](WEB_CONTROL.md#управление-и-потеря-связи)

## Приводы и датчики

- **Приводы.** `./ijk bench motors` проверяет STS3215 с вывешенными колёсами. При ошибке доступа к `/dev/ttySTS` проверьте группу `dialout` и [правило udev для Waveshare](../src/driver/udev/99-waveshare.rules). После добавления пользователя в группу начните новый сеанс входа.
- **Одометрия.** Базовый диаметр ведущих колёс — 75 мм, колея — 225 мм. `./ijk bench odom-calib` проводит линейный тест и разворот на свободной площадке. Измерьте пройденное расстояние и угол по подсказкам мастера. Откалиброванные диаметр колёс и колея записываются в `config/ijk.local.yaml`.
- **Лидар.** `./ijk bench lidar` проверяет RPLIDAR. Для A2M8 используются режим `Standard` и 115200 бод. Исходный скан приходит в `/scan_raw`, после фильтра колёс — в `/scan`. Задайте стабильный путь `/dev/serial/by-id/…` в `hardware.lidar.port`, если он доступен. Установка драйвера Slamtec описана в [инструкции по Jetson](JETSON_ORIN_MIGRATION.md#подготовка-платы-и-сборка).
- **Камера.** `./ijk bench camera` проверяет камеру. Для D435 сверьте, что устройство работает по USB 3.0, а цветовой режим выбран в `hardware.camera.color_profile`. Для 3D-картографии проверьте цвет, выровненную глубину и TF `base_footprint → camera_link` на борту. [Проверка D435 и QR](JETSON_ORIN_MIGRATION.md#камера-d435-и-qr)

Проверка маски колёс с работающим лидаром и TF:

```bash
ROS_DOMAIN_ID=42 python3 scripts/check_wheel_filter.py --seconds 5
```

Скрипт сопоставляет парные `/scan_raw` и `/scan` и проверяет, что попадания по колёсам удалены (`wheel_remaining=0`), а точки за пределами маски сохранены (`outside_removed=0`). Для проверки удаления в исходном скане должны быть попадания по колёсам. [Границы маски](../src/bringup/config/lidar_self_filter.yaml)

В штатной схеме `twist_mux` отдаёт приоритет аварийной остановке, затем джойстику, ручным командам и Nav2. При отсутствии свежих команд дольше 200 мс драйвер начинает плавную остановку. [Настройки приоритетов](../src/nav2/config/twist_mux.yaml)

## Картографирование и навигация

Для 2D-карты запустите `./ijk mapping`, для объединённой карты лидара и D435 — `./ijk mapping --3d`. Если камера и лидар установлены с отклонением от модели шасси, укажите измеренный файл креплений на борту через `--sensor-mounts-file` или `profiles.mapping.sensor_mounts_file`. При навигации с глубиной используется тот же файл, если для Navigate не задан собственный.

| Симптом | Что проверить |
| --- | --- |
| RViz показывает `No map received` или `No tf data` | Проверьте `/scan` и `/odom` на борту, публикацию `/map` и цепочку `map → odom → base_footprint → base_link → camera_link`. Сверьте ROS-домен, время и фиксированный фрейм `map`. Запускайте Mapping и Navigate последовательно, чтобы преобразование `map → odom` имело один источник. |
| 2D-карта есть, 3D-слой пуст | Проверьте, что выбран `mapping --3d`, подключена D435 и приходят выровненная глубина и цвет. В профиле RViz Mapping включите слой из `/terrain/rviz_map`. Изображение `/camera/preview/image_raw/compressed` проверяется в том же окне. |
| Пол выглядит как подъём, появляются ложные стены | Сверьте высоту и наклон D435 в TF на ровной площадке. В 3D-режиме фильтр ограничивает высоту глубины относительно `base_footprint`. После исправления креплений повторите съёмку в новой сессии. |
| Nav2 не строит маршрут по свободной дороге | Проверьте начальную позу AMCL и локальную карту стоимости. Отметки пола обрабатывает слой `FloorVoxelLayer`, а препятствия от глубины отмечаются начиная с 2,5 см над полом. При просрочке данных лидара или D435 более 0,5 с профиль блокирует движение. |

В веб-пульте можно сохранить `/map` кнопкой «Сохранить карту» во время Mapping, а затем выбрать её для Navigate. Там же доступны отдельные настройки RViz, AMCL и записи rosbag для профилей. Интеграции могут вызывать `GET /api/maps`, `GET /api/maps/{id}/preview`, `POST /api/maps/save` и проверять статус через `GET /api/jobs/{id}`. Для `POST /api/maps/save` передаются `name` и `stop_after`. [Контракты веб-пульта](WEB_CONTROL.md#контракты-интеграции)

## Соревновательный запуск

Сначала подготовьте карту и семантический снимок по [инструкции миссии](../src/brain/README.md). С загруженным снимком профиль `./ijk competition` запускает штатную миссию. Для зачётных заездов по мостам используется `./ijk competition --3d` и [проверенный эталон поверхности](../src/terrain/README.md).

При недоступности Ollama проверьте сервис и модель на ноутбуке с LLM:

```bash
curl http://localhost:11434/api/tags
ollama run qwen3.5:9b "Привет"
```

Правила этапов и схемы испытаний хранятся в [docs/competition](competition/). Для сценариев с прежними скриптами см. [scripts/legacy](../scripts/legacy/) и [инструкцию профиля «Город»](GOROD.md).
