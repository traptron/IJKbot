# Мосты в «Эвакуации»

Режим `competition --3d` добавляет проверку поверхности моста по D435 на Jetson. Для подготовки эталона используйте `mapping --bridge-survey`, который сохраняет независимую RGB-D траекторию с креном и высотой. На тренировке SLAM Toolbox строит `/map` по `/scan`. RTAB-Map строит 3D-карту и использует отдельный `/terrain/tf`. В зачёте AMCL локализуется по сохранённой 2D-карте, а RGB-D одометрия передаёт позу сообщениями. Для проекции глубины берём X, Y и рыскание из локализации по лидару, высоту, крен и тангаж из RGB-D одометрии. Исходные изображения глубины и облако используются бортовыми процессами.

## Проверка датчиков на Jetson

В бортовом workspace с собранными пакетами выполните:

```bash
source /opt/ros/jazzy/setup.bash
source install/local_setup.bash
ros2 launch bringup mapping.launch.py enable_3d:=true mock_hardware:=true \
  mapping_frame:=slam_map mapping_topic:=/terrain/slam_grid \
  terrain_session:="$HOME/ijk-terrain-check-$(date +%Y%m%d-%H%M%S)"
```

Этот запуск использует настоящий лидар и D435 с имитацией приводов. Проверьте `/scan`, `/camera/aligned_depth_to_color/image_raw` и `/terrain/visual_odom`. Для визуальной одометрии направьте камеру на сцену с контрастными деталями. Порт лидара можно выбрать аргументом `lidar_serial_port`, для последовательных портов на Ubuntu используется группа `dialout`.

## Снять пустые мосты

1. На Jetson соберите `terrain`, `bringup` и `nav2`. Для режима нужны ROS 2 Jazzy, RealSense ROS, RTAB-Map ROS, SLAM Toolbox и Nav2. Укажите SSH-пользователя и путь бортового workspace в `config/ijk.local.yaml`.
2. Проверьте размеры `camera_link` относительно шасси на ровном полу. Укажите измеренный YAML креплений через `--sensor-mounts-file` одинаково на тренировке и в зачёте. Поставьте робота в центр старта `(0.4, 0.4)`, вдоль оси +X арены.
3. Запустите `./ijk mapping --bridge-survey --terrain-session /путь/к/новому/каталогу`. Для геймпада подключите существующий `DS4_teleop` к `/cmd_vel_joy`. Для клавиатуры укажите `--teleop`. Медленно снимите настил и оба въезда с разных ракурсов. Замкните петлю и сравните два наблюдения въезда. Для проверки PointCloud2 в RViz на Jetson используйте фиксированный фрейм `rgbd_map` и `/terrain/slam/cloud_map`.
4. С неподвижного робота вызовите `ros2 service call /terrain/capture std_srvs/srv/Trigger '{}'`. В каталоге сессии сохранятся `cloud.npz` и `rtabmap.db`. Завершите запись после сохранения семантического снимка по инструкции. [README brain](../brain/README.md)

Подготовьте `review.json` с полями:

| Поле | Что измерить |
|---|---|
| `floor_anchors` | Массив пар `{"map":[x,y,z],"rgbd_map":[x,y,z]}` для одних и тех же точек. Нужно минимум три неколлинеарных ориентира на ровном полу. X, Y и Z в метрах. |
| `lane_polygons` | Полигоны подтверждаемой поверхности обоих мостов и подходов к ним. Каждый полигон — массив пар `[x,y]` в порядке обхода. |
| `deck_checks` | Полигоны контрольных участков ровного настила внутри полосы, на 55 мм выше пола. |
| `keepout_polygons` | Полигоны ограждений и опасных участков по бокам. Участки полосы и запретные зоны должны иметь общую границу без зазора. |
| `calibration` | Результаты измерений из таблицы ниже. |

| Параметр калибровки | Как получить |
|---|---|
| `residual_m` | Допуск по высоте между повторными съёмками пустого въезда. Проверьте, что минимальный выступ машинки превышает допуск. |
| `max_pose_error_m` | Запас на совмещение 2D и 3D по контрольным точкам. Используется также для допуска по горизонтальной дисперсии AMCL. |
| `braking_decel_m_s2`, `angular_decel_rad_s2` | Нижние оценки замедления на собранном роботе с учётом нагрузки и уклона. |
| `reaction_sec` | Верхняя оценка задержки от съёмки до начала замедления, включая истечение разрешения, обработку и 200 мс сторожевого таймера. Минимум 0.6 с. |
| `max_speed_m_s` | Проверенная скорость на мосту, максимум 0.15 м/с. |
| `clear_ttl_sec` | Срок подтверждения осмотренной ячейки, пока продолжают приходить пригодные кадры. Проверьте на медленном въезде, что закрытый корпусом настил сохраняет подтверждение на время его проезда. |
| `footprint_margin_m` | Измеренный запас для корпуса и выступающих деталей, минимум 0.05 м. |

Постройте эталон на компьютере, где доступны файлы сессии и семантическая карта:

```bash
ros2 run terrain bridge_snapshot.py build \
  --arena snapshot/arena.json --review review.json \
  --cloud session/cloud.npz --database session/rtabmap.db \
  --output snapshot/bridge.json
ros2 run terrain bridge_snapshot.py preview snapshot/bridge.json
```

В RViz включите `/terrain/markers` во фрейме `map` и проверьте совпадение карты, полосы и ограждений. Храните базу RTAB-Map, облако и эталон вместе со снимком арены. Эталон хранит контрольные суммы исходников и версию снимка. Ячейка сетки высот имеет сторону 2 см.

## Зачёт и проверка

```bash
IJKBOT_ARENA_FILE=/путь/к/снимку/arena.json ./ijk competition --3d
```

Стартуйте с той же ровной точки для нулевой высоты RGB-D одометрии. Глобальный слой повышает стоимость непроверенного проезда и закрывает препятствия. Локальный слой запрещает движение в непроверенную часть. Перед драйвером каждая команда проходит проверку площади, которую корпус займёт за задержку и торможение. В RViz зелёные ячейки обозначают подтверждённую поверхность, жёлтые — неизвестную, красные — препятствия и запретные зоны. `/terrain/status` показывает причину остановки. Версия 3D-эталона должна совпадать с версией утверждённой карты.

В 3D-профиле нативный QR-декодер работает на Jetson с цветным JPEG-потоком D435. На ноутбук передаются текст и сжатый кадр прочитанного QR, судейский дашборд и LLM запускаются на ноутбуке.

На Jetson запишите стендовые проезды с пустым въездом, машинкой на въезде, настиле и у ограждения. Для ROS bag запишите `/camera/color/image_raw`, `/camera/color/camera_info`, `/camera/aligned_depth_to_color/image_raw`, `/scan`, `/odom`, `/tf` и `/tf_static`. Для проигрывания, которое подаёт записанные `odom → base_footprint`, используйте `terrain_competition.launch.py` с `replay:=true enable_lidar:=false enable_motors:=false use_sim_time:=true`, `map:=...` и `bridge_reference:=...`. Для нового AMCL в replay исключите записанные преобразования `map → ...` из rosbag. Проверьте, что при пустом мосте есть сквозной путь, а при препятствии Nav2 выбирает объезд или сообщает об остановке. При потере кадров проверьте дистанцию остановки. Перед зачётом повторите измерения на настоящем мосту при работающих QR и Nav2.
