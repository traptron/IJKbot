# IJKbot — Руководство оператора (Ноутбук 2) и описание скриптов

Данная директория содержит набор автоматизированных скриптов для управления мобильным роботом **IJKbot** в рамках соревнований «Хакатон Эвакуация» (Кубок РТК Высшая Лига, Ижевск).

---

## 1. Архитектура и распределение ролей между машинами

В соревновательном заезде участвуют 3 вычислителя в единой локальной сети:

```text
       ┌────────────────────────────────────────────────────────┐
       │             Роутер соревнований 5 ГГц                  │
       │                   ROS_DOMAIN_ID=42                     │
       └───────┬───────────────────┬───────────────────┬────────┘
               │                   │                   │
               ▼                   ▼                   ▼
    ┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐
    │  Машина 1        │  │  Машина 2        │  │  Машина 3        │
    │  (Ноутбук 1)     │  │  (Ноутбук 2,     │  │  (Raspberry Pi   │
    │  IP: 192.168.1.20│  │   этот ноутбук)  │  │   4B на роботе)  │
    │                  │  │  IP: 192.168.1.30│  │  IP: 192.168.1.10│
    ├──────────────────┤  ├──────────────────┤  ├──────────────────┤
    │ • Ollama LLM     │  │ • SSH управление │  │ • Драйвер STS3215│
    │   (Qwen 2.5 7B)  │  │   роботом        │  │ • RealSense D435 │
    │ • NiceGUI Web    │  │ • Nav2 навигация │  │ • LaserScan /scan│
    │   Dashboard      │  │ • RViz2 (Pixi)   │  │ • TF odom->base  │
    │ • State Machine  │  │ • Телеуправление │  │ • Watchdog 200мс │
    └──────────────────┘  └──────────────────┘  └──────────────────┘
```

1. **Машина 1 (Ноутбук 1, не этот)**: Запускает сервер LLM Ollama, конечный автомат миссии и судейский дашборд NiceGUI (`dashboard_app.py`, порт 8080).
2. **Машина 2 (Ноутбук 2, данный компьютер — рабочее место оператора)**:
   - Подключается по SSH к Raspberry Pi.
   - Запускает базовый стек робота (`robot.launch.py`) и навигацию (`navigation.launch.py`).
   - Запускает `rviz2` в изолированном окружении Pixi ROS 2 Jazzy.
   - Обеспечивает ручной телеоп при проверке вывешенных колёс и экстренное торможение.
3. **Машина 3 (Raspberry Pi 4B, борт робота)**: Приводы Feetech STS3215 (USB-UART `/dev/ttyUSB0`), камера Intel RealSense D435, одометрия 50 Гц, TF-дерево.

## 3. Детальное описание каждого скрипта

### 3.1. `start_all_laptop2.sh` — Главный командный центр
Оркестратор автоматизирует полный предстартовый пайплайн Ноутбука 2:
1. Проверяет ping к Raspberry Pi (`192.168.1.10`, при недоступности проверяет резервный хотспот `172.22.35.154`).
2. Запускает проверку синхронизации часов Chrony. Если $|\Delta t| \ge 5.0\text{ мс}$, выдаёт строгое предупреждение с запросом подтверждения у оператора.
3. Запускает удалённо `robot.launch.py` на Raspberry Pi (логи выводятся в `log/robot_pi.log`).
4. Ожидает 4 секунды и запускает стек автономной навигации `navigation.launch.py` (логи в `log/nav2_pi.log`).
5. Запускает `rviz2` в основном окне.
6. При закрытии окна RViz2 или нажатии **Ctrl+C** автоматически вызывает `stop_all.sh`, останавливает моторы и гасит удалённые процессы.

**Режимы запуска (`--mode`):**
- `bg` (по умолчанию): фоновый запуск удалённых процессов с перенаправлением логов в файлы `log/*.log` и RViz2 на переднем плане.
- `tabs`: открывает отдельные вкладки терминала (`ptyxis` / `gnome-terminal`) для каждого компонента.
- `windows`: открывает отдельные окна для каждого компонента.
- `tmux`: запускает сессию `ijkbot` в tmux с окнами `robot`, `nav2`, `rviz`.

**Полезные флаги:**
```bash
./scripts/start_all_laptop2.sh --mock --local       # Автономный прогон полного стека локально на Ноутбуке 2
./scripts/start_all_laptop2.sh --mode tabs          # Запуск в отдельных вкладках Ptyxis
./scripts/start_all_laptop2.sh --no-rviz            # Запуск только фонового стека без GUI
./scripts/start_all_laptop2.sh --use-amcl           # Запуск с AMCL локализацией вместо статического TF
./scripts/start_all_laptop2.sh --map <PATH>         # Указать пользовательскую карту полигона
./scripts/start_all_laptop2.sh --force              # Игнорировать сетевые проверки при нестандартном сетапе
./scripts/start_all_laptop2.sh --skip-sync          # Пропустить проверку расхождения часов
```

### 3.2. `start_robot_pi.sh` — Базовый стек на Pi
Запускает на борту робота (или локально через Pixi):
- `rsp.launch.py` (URDF модель робота, TF `base_footprint -> base_link -> camera_link`).
- Сенсоры: Intel RealSense D435 и ноду `depthimage_to_laserscan` (публикация `/scan`).
- Драйвер моторов `diff_drive_node` (управление STS3215, одометрия 50 Гц в топик `/odom` и TF `odom -> base_footprint`).
- Перехватывает SIGINT/SIGTERM и удалённо гасит `diff_drive_node` и ноды сенсоров с освобождением USB/UART.

```bash
./scripts/start_robot_pi.sh                         # Запуск на реальном роботе (192.168.1.10)
./scripts/start_robot_pi.sh --host 172.22.35.154   # Запуск через мобильную точку
./scripts/start_robot_pi.sh --mock                  # Запуск в режиме имитации без UART
./scripts/start_robot_pi.sh --mock --local          # Локальный запуск на Ноутбуке 2 через Pixi
```

### 3.3. `start_nav2_pi.sh` — Автономная навигация Nav2
Запускает навигационные компоненты:
- `map_server`: статическая карта полигона соревнований 4×4 м (настраивается флагом `--map`).
- Локализация: чисто одометрическая со статическим TF `map -> odom` (по умолчанию) либо AMCL (`--use-amcl`).
- `controller_server` (Regulated Pure Pursuit) и `velocity_smoother`.
- `planner_server` (Navfn / A*).
- `bt_navigator` (принимает цели `/goal_pose` от дашборда и LLM).
- `twist_mux`: арбитраж команд скорости.

```bash
./scripts/start_nav2_pi.sh                          # Удаленный запуск на Pi по SSH
./scripts/start_nav2_pi.sh --initial-x 0.4 --initial-y 0.4 --initial-yaw 0.0
./scripts/start_nav2_pi.sh --map /path/to/map.yaml  # Пользовательская карта
./scripts/start_nav2_pi.sh --local                  # Локальный запуск на Ноутбуке 2 через Pixi
```

### 3.4. `start_rviz.sh` — Визуализация в RViz2
Запускает RViz2 через изолированное окружение Pixi ROS 2 Jazzy:
```bash
./scripts/start_rviz.sh
```
Использует файл конфигурации [`ijkbot_nav2/rviz/nav2_default_view.rviz`](file:///home/lev/IJKbot/ijkbot_nav2/rviz/nav2_default_view.rviz):
- **Сетка полигона (800 мм)**: соответствует разметке ячеек полигона соревнований.
- **RobotModel & TF**: кинематическая 3D-модель IJKbot и дерево координат.
- **LaserScan `/scan`**: дальномерные лучи препятствий от RealSense.
- **Global & Local Costmaps**: карты проходимости с радиусом инфляции безопасности (защита от касаний `-70` баллов).
- **Footprint**: физический габарит шасси робота в движении.
- **Global & Local Plans**: рассчитанная траектория движения к цели.
- **QR Camera (Green Box)**: трансляция с камеры `/vision/qr/image/compressed` с подсветкой распознанного QR-кода зелёной рамкой для демонстрации судьям.

### 3.5. `stop_all.sh` — Экстренная и штатная остановка
Критически важный скрипт безопасности:
1. Немедленно публикует нулевую скорость `Twist(0, 0)` в топик `/cmd_vel_emergency` (наивысший приоритет 100 в `twist_mux`), `/cmd_vel_sm` (50) и `/cmd_vel` без блокировок (`-w 0`).
2. Завершает все удалённые процессы на Raspberry Pi (`robot.launch.py`, `navigation.launch.py`, `diff_drive_node`, `realsense2_camera_node`, `nav2_*`, `static_transform_publisher`).
3. Завершает локальные процессы на Ноутбуке 2 (`rviz2`, `teleop_twist_keyboard`, фоновые скрипты), не убивая вызывающий родительский процесс.

```bash
./scripts/stop_all.sh               # Мягкая штатная остановка робота и Ноутбука 2
./scripts/stop_all.sh --local       # Локальная остановка только на Ноутбуке 2 (без SSH)
./scripts/stop_all.sh --force       # Экстренное принудительное завершение (SIGKILL)
./scripts/stop_all.sh --caller-pid $$ # Вызов из родительского скрипта с защитой родителя
```

### 3.6. `teleop.sh` — Телеуправление с клавиатуры
Используется для проверки робота на весу (вывешенные колёса) и ручной корректировки.
Команды отправляются в топик `/cmd_vel_sm` (приоритет 50 в `twist_mux`):
- Перехватывает управление у автономной навигации Nav2 (приоритет 10).
- При этом уступает аварийной остановке `/cmd_vel_emergency` (приоритет 100).
- Автоматически ограничивает скорость до $0.25\text{ м/с}$ по регламенту соревнований (защита от штрафа `-70` баллов).
- При выходе по Ctrl+C гарантированно перехватывает сигнал и отправляет нулевую скорость.

```bash
./scripts/teleop.sh
./scripts/teleop.sh --speed 0.2     # Установка безопасной линейной скорости
```

**Раскладка клавиш:**
- `u` / `i` / `o` — Вперёд-влево / Вперёд / Вперёд-вправо
- `j` / `k` / `l` — Разворот влево / СТОП / Разворот вправо
- `m` / `,` / `.` — Назад-влево / Назад / Назад-вправо
- `пробел` — Экстренный СТОП
- Лимит скорости по умолчанию: $0.20\text{ м/с}$ (максимум по регламенту: $0.25\text{ м/с}$).

### 3.7. `update_pi.sh` — Обновление репозитория и сборка пакетов
Утилита автоматизирует процесс синхронизации кодовой базы на бортовом компьютере Raspberry Pi 4B (или локально на Ноутбуке 2) и последующей сборки пакетов ROS 2:
1. **Синхронизация Git**:
   - Выполняет `git fetch` и `git pull` целевой ветки (по умолчанию `dev`).
   - Поддерживает выбор любой ветки через аргумент `--branch <BRANCH>`.
2. **Безопасная обработка рабочего каталога**:
   - При наличии незакоммиченных изменений (например, оперативная калибровка на роботе) автоматически сохраняет их в `git stash push` перед обновлением.
   - После успешного `git pull` автоматически восстанавливает изменения через `git stash pop`.
   - При необходимости авто-stash можно отключить флагом `--no-stash`.
3. **Автоматическая сборка ROS 2 (Jazzy)**:
   - Автоматически находит измененные ROS-пакеты и выполняет инкрементальную сборку: `colcon build --symlink-install --packages-up-to <pkgs>`.
   - При установленном флаге `--clean` производит полную очистку (`rm -rf build/ install/ log/`) перед сборкой.
   - Флаг `--no-build` позволяет только обновить репозиторий без компиляции.
   - Поддержка явного указания пакетов через `--packages <PKGS>`.
4. **Удобство запуска (удаленно и локально)**:
   - **Удаленный режим (по умолчанию на ноутбуке)**: подключается по SSH к Raspberry Pi (`otmorozki@192.168.1.10`), проверяет доступность хоста, запускает процедуру обновления и транслирует лог компиляции в терминал оператора.
   - **Локальный режим**: выполняется напрямую при запуске на Raspberry Pi (автоопределение) или при передаче флага `--local` на Ноутбуке 2.

```bash
./scripts/update_pi.sh                         # Удаленное обновление робота по SSH (192.168.1.10, ветка dev)
./scripts/update_pi.sh --host 172.22.35.154   # Обновление через мобильную точку доступа
./scripts/update_pi.sh --branch main          # Обновление ветки main
./scripts/update_pi.sh --clean                # Чистая пересборка всех пакетов на роботе
./scripts/update_pi.sh --no-build             # Только git pull без colcon build
./scripts/update_pi.sh --packages sts3215_driver # Сборка только конкретного пакета
./scripts/update_pi.sh --local                # Обновление и сборка локального репозитория
```

## 4. Чеклист оператора перед соревновательным заездом (5 мин)

Во время 5-минутной фазы подготовки на полигоне выполните следующие шаги:

```text
[ ] 1. Подключить Ноутбук 2 к 5 ГГц Wi-Fi роутеру соревнований (SSID: rtk_evacuation).
       Убедиться, что получен IP (192.168.1.30).
[ ] 2. Включить питание робота (тумблер 4S LiPo). Проверить индикатор RealSense.
[ ] 3. Проверить связь и расхождение часов:
       python3 scripts/check_clock_sync.py
       -> Должен быть статус: [PASS] |Δt| < 5.0 мс
       (Если FAIL: выполнить ./scripts/setup_chrony.sh deploy-pi)
[ ] 4. Вывесить ведущие колеса робота и запустить тест моторов:
       ./scripts/teleop.sh
       -> Нажать 'i' (вперед): оба колеса должны вращаться вперед.
       -> Проверить ID приводов: левый ID 1, правый ID 2.
[ ] 5. Поставить робота в стартовую ячейку (центр ячейки: X=0.4, Y=0.4, нос вдоль оси X).
[ ] 6. Запустить единый оркестратор:
       ./scripts/start_all_laptop2.sh
[ ] 7. В открывшемся окне RViz2 проверить:
       - Отображение сетки 800 мм и карты полигона.
       - Красные точки лазерскана /scan (препятствия).
       - Видеопоток камеры с QR-кодом (вкладка Displays -> QR Camera).
[ ] 8. Доложить судьям о готовности к старту 5-минутного соревновательного заезда.
```

## 5. Устранение неполадок (Troubleshooting)

### 1. Робот не отвечает на ping (`192.168.1.10`):
- Проверьте, подключен ли робот к Wi-Fi роутеру соревнований.
- Если роутер недоступен и задействована мобильная точка доступа со смартфона, запустите:
  ```bash
  ./scripts/start_all_laptop2.sh --host 172.22.35.154
  ```

### 2. Ошибка рассинхронизации часов Chrony ($|\Delta t| > 5.0\text{ мс}$):
- Разница времени приводит к дропам TF в Nav2 (`ExtrapolationException`).
- Выполните деплой и синхронизацию:
  ```bash
  ./scripts/setup_chrony.sh deploy-pi
  python3 scripts/check_clock_sync.py
  ```

### 3. Моторы STS3215 не реагируют на `/cmd_vel`:
- Проверьте питание силовой части (14.8В от аккумулятора LiPo).
- Проверьте доступ к адаптеру Waveshare USB-UART на Raspberry Pi:
  ```bash
  ssh otmorozki@192.168.1.10 "ls -la /dev/ttyUSB0"
  ```
- Если устройство заблокировано другим процессом, выполните `./scripts/stop_all.sh` и перезапустите.

### 4. Не открывается окно RViz2:
- Убедитесь, что переменная окружения `DISPLAY` или `WAYLAND_DISPLAY` установлена:
  ```bash
  echo $DISPLAY
  ```
- Запустите напрямую через Pixi для просмотра подробного трейсбека:
  ```bash
  ./scripts/start_rviz.sh
  ```
