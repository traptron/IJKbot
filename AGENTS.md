# AGENTS.md — Инструкция для AI-агентов по работе с репозиторием IJKbot

Этот документ определяет правила, контекст, соглашения и протоколы взаимодействия для любых AI-агентов (включая Antigravity, специализированные субагенты и парных ассистентов), работающих с кодовой базой **IJKbot**.

---

## 1. Контекст проекта и цели

**IJKbot** — это двуколесная мобильная платформа дифференциального привода, созданная для участия в хакатоне «Эвакуация» (соревнования «Кубок РТК Высшая Лига», Ижевск).

### 1.1. Регламент и система оценивания:
- **Языковая модель верно интерпретировала команду**: `+100` баллов.
- **Найден пострадавший человек**: `+160` баллов.
- **Получена информация о состоянии пострадавшего (с QR-кода)**: `+80` баллов.
- **Пострадавший эвакуирован в пункт сбора (стартовая ячейка)**: `+160` баллов.
- **Столкновение/касание с объектом полигона**: `-70` баллов (Критично: любое касание штрафуется жестко!).
- **Ограничения по времени**: 5 минут на подготовку (ввод текста, работа LLM), 5 минут на выполнение миссии.
- **Судейский контроль**: По требованию судьи необходимо визуально продемонстрировать работу датчиков и вывести понятные логи системы.

## 2. Аппаратный состав и сетевая топология

### 2.1. Бортовой компьютер (Робот):
- **Модель**: Raspberry Pi 4B.
- **ОС и стек**: Ubuntu 24.04.05 LTS, нативный **ROS 2 Jazzy**.
- **Приводы**: 2× смарт-сервопривода Feetech STS3215 (передние ведущие колеса) + переходник Waveshare USB-to-UART (`/dev/ttyUSB0`, 1 000 000 бод).
- **Сенсор**: Intel RealSense D435 (подключена по USB 3.0).
- **Геометрия**:
  - Диаметр колес: $D = 75\text{ мм}$ ($R = 0.0375\text{ м}$).
  - Колея ведущих колес по центрам шин: $L = 225\text{ мм}$ ($0.225\text{ м}$), из размеров 200 мм по внутренним и 250 мм по внешним сторонам.
  - Расстояние между передней и задней осью: 140 мм; ширина каждой ведущей шины при одинаковых колесах: 25 мм.
  - ID приводов: левый — 1, правый — 2. Знаки вращения проверяются на вывешенных колесах.
  - Опоры: два задних пассивных кастера по углам шасси.
- **Питание**: 4S LiPo 14.8В 5000 мАч.

### 2.2. Внебортовой вычислитель (Ноутбук):
- **GPU**: NVIDIA GeForce RTX 5060 (8 ГБ VRAM).
- **Стек**: Ollama (модель `qwen2.5:7b-instruct-q4_K_M`), PyTorch / TensorRT, YOLO-World, OpenCV, PyZBar, NiceGUI.

### 2.3. Сеть и связь:
- **Роутер**: Выделенный 5 ГГц Wi-Fi роутер, статические IP (Pi: `192.168.1.10`, Ноутбук: `192.168.1.20`).
- **DDS**: CycloneDDS / FastDDS с фиксированным `ROS_DOMAIN_ID=42`.
- **Ограничение трафика**: Запрещено передавать сырые PointCloud2 или несжатое видео по Wi-Fi. Видео передается исключительно через `image_transport/compressed` (JPEG, 640×480).

## 4. Правила и соглашения для агентов

### 4.1. Безопасность и работа с приводами:
1. **Безопасность моторов**: Сервоприводы STS3215 обладают высоким крутящим моментом (до 30 кг·см). При написании и тестировании драйвера **всегда** предусматривайте:
   - Флаг симуляции / мока (например, параметр `mock_hardware:=true`), позволяющий компилировать и тестировать логику одометрии и TF без реального подключения к UART.
   - Аппаратный Watchdog: если нода не получает команд из `/cmd_vel` дольше 200 мс, моторы должны автоматически плавно останавливаться.
2. **Предотвращение касаний (-70 баллов)**:
   - Никогда не уменьшайте `inflation_radius` в `nav2_params.yaml` ниже безопасного порога (радиус робота + 50 мм).
   - Максимальная скорость движения на полигоне $V_{max} \le 0.25\text{ м/с}$.

### 4.2. Стандарты кода:
- **C++ (пакет `sts3215_driver`)**:
  - Стандарт: C++17.
  - Следовать ROS 2 C++ Style Guide.
  - Использовать `rclcpp::Node`, явное управление памятью, умные указатели (`std::shared_ptr`, `std::make_shared`).
  - Обязательно обрабатывать возможные ошибки UART (таймауты, битые пакеты, контрольные суммы CRC/Checksum) без аварийного падения ноды.
- **Python (пакеты `ijkbot_vision`, `ijkbot_brain`)**:
  - Стандарт: Python 3.12 (нативный для Ubuntu 24.04).
  - Типизация (`typing`), датаклассы или Pydantic для контрактов сообщений.
  - Асинхронность и интеграция с ROS 2: использовать `rclpy` executor без блокировки GUI или фонового инференса нейросетей.
- **Форматирование и целостность**:
  - Не удалять существующие комментарии, docstrings и лицензии.
  - Использовать понятные имена топиков и сервисов в snake_case.

### 4.3. Работа с LLM (Ollama & Qwen 2.5):
- Все запросы к LLM должны использовать **Structured Outputs / JSON Mode**.
- Ответ LLM должен быть строго ограничен Pydantic-схемой с полями `target_landmark_id`, `search_strategy`, `reasoning`.
- Никакого свободного неструктурированного текста на выходе модели, так как результат демонстрируется судьям и передается в автомат состояний.

### 4.4. Протокол проверки изменений (Verification):
При создании или изменении функционала агент обязан:
1. Проверить сборку пакетов:
   ```bash
   colcon build --symlink-install --packages-select <package_name>
   ```
2. Проверить синтаксис и линтеры:
   - C++: отсутствие предупреждений компилятора.
   - Python: `flake8` или базовый синтаксический чекер `python3 -m py_compile <file.py>`.
3. При изменении TF или одометрии:
   - Убедиться, что дерево координат замкнуто: `map -> odom -> base_footprint -> base_link -> camera_link`.

## 5. Взаимодействие между агентами и человеком

- **Следование плану**: Агенты должны строго сверяться с [PLAN.md](file:///home/lev/IJKbot/PLAN.md) и реализовывать функционал поэтапно.
- **Не внедрять код до явного подтверждения**: Если пользователь попросил подготовить план/документацию без внедрения (как в текущем запросе), агент ограничивается проектными документами и не создает пустые или недоделанные исходники.
- **Прозрачность для судей**: Любая критическая логика должна сопровождаться логированием через стандартный механизм `RCLCPP_INFO` / `node.get_logger().info(...)`, чтобы в судейском дашборде формировалась чистая хронология событий.
